# 03 · 写入管线

> 对应 v0.16.2。入口：`turn/end` 事件；实现：`lib/pipelines/write.js`（决策门在 `lib/write-gate.js`，提取在 `lib/refiner.js`）。
> 一句话：**一轮对话结束时，判断值不值得记 → 值得就蒸馏成自包含记忆 → 与既有记忆去重合并 → 建图 → 必要时触发管家**。

## 3.1 全流程

```
turn/end 事件
  → turnCache：攒本轮 user / assistant 文本（只收 source.kind==='user' 的真实消息，防注入嵌套）
  → 价值门 isTrivialTurn()           ← features.valueGate
       空 / 纯寒暄 / 无成果信号 → 丢弃，不写库
  → 写入侧决策门 createWriteGate()   ← features.writeGate（默认关）
       本机决策模型高把握答"不值得" → 落一条 ep 快照后结束（记录不丢，只省掉 LLM）
       其余一切情形（服务没起 / 超时 / 形状不对 / 没把握 / 取消）→ 照常往下走
  → 提取
       refiner.enabled ? extractWithLlm()  → { content, type, layer, keywords, abstract, theme, aspect }
                        ↑ 失败 / 超时 → 降级规则路径
                        : 规则组装（"任务: … 结果: …"）
  → upsertMemory()
       Jaccard ≥ 0.8 且开启 dedupMerge → update（追加版本 + strength 加成，同 id 不新建）
       否则                            → add
  → 同步写 memories_fts + memory_vectors + memory_versions（features.time）
  → features.graph → graphLink（实体共现）+ linkSimilar / linkBefore（记忆级边）
  → maybeHousekeeping()：写入量或时间任一到期 → 管家巡检
```

## 3.2 价值门（`isTrivialTurn`）

两道判据，**保守优先**（宁可多记一条，也不要把用户的短表达当寒暄丢掉）：

| 判据 | 规则 |
|---|---|
| 助手有实质输出 | 助手侧非空且长度 ≥ 4 → 这一轮有产出，直接算有价值，不再看用户侧 |
| 用户消息是纯寒暄 | 整条消息只由 `TRIVIAL_MSG_RE` 覆盖的客套词构成（继续 / 好的 / 早上好 / 谢谢 / ok …）→ 丢弃 |
| 但含信号词则保留 | 命中 `SIGNAL_RE`（`不要` `必须` `改成` `以后` `我认` `偏好` `不是这样` `我的意思` …）→ **不算寒暄**，照常沉淀 |

最后一条来自实测：用户大量高价值表达本身就极短（"不要堆代码""用大白话""改成 12 步""我认"）。

## 3.3 写入侧决策门（v0.16.0）

把"这一轮值不值得送 LLM 提取"交给本机决策模型（StartLux-Decision 9B，HTTP `127.0.0.1:8090/v1/systemone`，输出 0 token，实测 0.3~0.9 秒），省掉的是一次几十秒的 LLM 提取。

**采信规则是非对称的**，这是本模块唯一要紧的约定：

| 决策模型返回 | 行为 |
|---|---|
| `worth === false` 且把握度 ≥ `decision.writeMinConfidence`（默认 0.9） | 改变行为：不调用提取器，改落一条 ep 快照 |
| `worth === true` | 照常提取 |
| 把握度不足 / `worth` 非布尔 | 照常提取（`worth: null`） |
| 服务没起 / 超时（默认 2s）/ HTTP 错 / 返回形状不对 / 本轮被取消 | 照常提取 |

理由：反方向判错（其实不值得却去提取）只多花一次 LLM；判错成"不值得"则是**少记一条，不可逆**。
失败后进冷却（5 分钟）避免每轮都白等一次超时。

> **检索路径上没有决策门**（2026-10-06 定）：用户消息来了就直接查库，不问"要不要查"。查库是注入链路的本职，加一道判断只会在关键路径上多花时间，还要承担"判错就漏检索"的风险。

## 3.4 提取器（`lib/refiner.js`）

| 机制 | 说明 |
|---|---|
| 不设 token 上限 | `maxTokens: 0` = 不传该参数；约束交给时间预算。**强制思考的模型会把 token 额度全花在 reasoning 上**，正文一个字不剩（见 [08-配置与双内核](08-配置与双内核.md) §误配置护栏） |
| 时间预算 + 断点续跑 | `timeBudgetMs`（默认 120s）到点掐断，**带着已写内容续跑**（`maxContinuations` 默认 3），续跑写不出东西自动停 |
| 瞬时故障重试 | 只重发网络错 / 5xx / 流畸形（`TRANSPORT`、`event precedes message_start`）；**429 与 400 不重发**。指数退避，默认 2 次、封顶 8s |
| 松 JSON 解析 | `parseJsonLoose` + `repairTruncatedJson`：坏 JSON、被截断的 JSON 都尽力救回 |
| 关思考姿势按 provider 分派 | 默认 `reasoningEffort: off`。pi-ai 走"不带该字段"，官方 Messages 路由显式传 `off`——`reasoningParam()` 负责翻译 |
| 双输出 | 每条记忆带 `abstract`（principle / event）与 `theme`（名词标签，如"四级备考"） |
| 产出 0~3 条 | 先写 `analysis` 判断，再产出 items；寒暄 / 空转轮次直接不记 |
| 失败降级 | 任何失败 → 规则路径（`任务: … 结果: …`），记录照落，只是形态退化 |

## 3.5 去重合并与"纠正既有记忆"

- **去重合并**：新内容与既有记忆的 Jaccard ≥ 0.8 → 走 `update`（同一个 id 追加版本 + strength 加成），而不是新建一条并存的。
- **纠正分支（v0.12.2）**：提取时把库里已有的相关记忆（`knownTopN` 默认 5 条）一并交给模型，让它判断这轮是在**推翻/更正**旧记。若是，走更新分支（旧内容进世界线、可回滚）。
- **id 白名单校验**：模型编出来的 id 改不动无关记忆——只有它确实见过的 id 才被接受。

## 3.6 会话级汇总（v0.12.2）

逐轮提取之外再补一层：攒够 `sessionSummary.rounds`（默认 12）轮，把这段对话交回模型总结成 0~3 条结论——"整段会话最后落在哪里"。同一个决定被反复修改过时，只写最后落定的那个。

## 3.7 scope 分层

写入口的 scope 规则（唯一判据在 `lib/util.js scopeOf`）：

| 情况 | scope |
|---|---|
| `type === 'profile'` | `global`（画像固定公共层） |
| 会话能解析出工作目录 | 该目录对应的 scope |
| 能解析出工作区（workspaceRegistry） | 该工作区 scope |
| 都不行 | `global` |

存入项目 scope 的记忆，注入时会与 `global` 一起被检索（见 [05-注入管线](05-注入管线.md)），存量 `global` 记忆兼容为公共层。

## 3.8 图谱连边与管家触发

- `features.graph` 开启时，写入后建实体共现（`graphLink`，泛词不成节点）与记忆级边（`linkSimilar` 向量判定、`linkBefore` 时间演化链）。
- 管家触发与对话轮数解耦：**每沉淀 `housekeeping.interval`（默认 20）条记忆**，或**距上次巡检超 `maxIntervalHours`（默认 24）小时**，两者任一到期即巡检。详见 [07-遗忘与管家](07-遗忘与管家.md)。
