# 11 · 已知限制与演进

> 对应 v0.16.2。这里写"现在做不到 / 有代价 / 待改"的事，以及几条用真实代价换来的教训。

## 11.1 已知限制

| 项 | 说明 |
|---|---|
| 社区检测全量重算 | `detectCommunities` 每次重建全部社区，没有增量版本（主题与事件都有增量） |
| 部分边型需人工 / 模型判断 | `causes` `solves` `supports` `contradicts` 四型没有自动建边，靠 `memory_graph_link` 手动连 |
| 图谱快照直读 `store.db` | `graph-snapshot.js` 里为拿版本数与记忆级边直接 prepare 了 SQL，属遗留封装修复点——理想是在 `store.js` 补访问器（`versionCounts()` / `activeLinks()`） |
| 快照上限 | 只取 `sm` 层、上限 1000 条记忆——大库时图谱是"抽样视图" |
| 检索依赖嵌入质量 | 远程嵌入不可用时降级到 rule 哈希，语义检索精度显著下降（FTS / 关键词仍正常） |
| `deploy.mjs` 路径写死 | 默认家目录假设，DSH_HOME 不在默认位置时认不出真在跑的实例；且它不会自动重建 `lib/client.js`，改过前端要另外跑 `build-client.mjs` |

## 11.3 五条换来代价的教训

这几条不是理论，每一条都对应一次真实故障。写在这里是因为**它们决定了上面各章为什么长这样**。

### ① 缺失的命名导出 = 宿主 exit 1

`@deepseek-ai/dsh-settings` 删掉 `settingsNamespace` 后，静态 import 会在**模块求值期**抛 SyntaxError，cordis 记为 entry 加载失败，**宿主直接 exit 1**。
与"服务不存在"完全不同——后者被 `ctx.inject` 静默降级，前者没有第二次机会。
⇒ 兼容层只做动态 import + 特性探测（见 [08](08-配置与双内核.md) §8.2）。

### ② 调 `llm.stream` 不传 sessionId = 整条链路瘫 7 天

2026-09-16 ~ 09-23，提取链路连续七天不工作。真因：调用 `ctx.llm.stream` 时没传 `sessionId`。
⇒ 所有 LLM 调用一律显式带上会话身份。

### ③ 流式 API 的失败藏在终止块里

DSH 的流式调用**不在中途抛异常**：400 / 配额 / 空响应 / 上下文溢出 / 超时全部编码进终止块的 `reason`（`kind: 'stop'` 但内容为空也算失败）。
只看"有没有抛错"会得出"一切正常"的错误结论。
⇒ 判定必须解终止块（见 [09](09-集成点与工具面.md) §9.4）。

### ④ 强制思考的模型 + maxTokens = 正文一个字不剩

token 额度全花在 reasoning 上，正文 0 字 → JSON 解析必失败 → 提取持续降级，而日志里只有一行 warning。
⇒ `maxTokens: 0`（不传）+ 启动期护栏（见 [08](08-配置与双内核.md) §8.8）。

### ⑤ 探针必须与被检真实路径同构

自检 / 探针类代码若与真实路径不同构，会**稳定地误报**："提取模型不可用"而实际提取是好的。
⇒ 探针发与真实提取同构的请求（同类任务、同样参数形态），否则探针本身才是故障源。
