# 06 · 图谱与社区

> 对应 v0.16.2。数据访问：`lib/store.js`；判定：`lib/link-suggest.js`；投影：`lib/graph-snapshot.js`；绘制：`client/graph*.js*`。

## 6.1 两层图结构

| 层 | 存储 | 用途 |
|---|---|---|
| **记忆级边** | `memory_links` | 一等数据源。GUI 投影直读，记忆级 BFS / k-hop 邻域走它。8 型语义边直接落"记忆对"，不绕实体节点 |
| **实体骨架** | `nodes` / `edges` / `node_memories` | 记忆里的实体（人名、项目名、技术词）作为节点，`mentions` 是共现边 |

早期版本只有实体层，画图时要靠实体回查记忆（`memOf`）。v0.9.x 起记忆级边独立成表，投影不再做映射。

## 6.2 8 型边与自动建边范围

`EDGE_TYPES`：`mentions` `partOf` `similarTo` `causes` `solves` `before` `supports` `contradicts`。

| 边型 | 谁建的 | 判据 |
|---|---|---|
| `mentions` | 写入管线自动 | 两条记忆共享 ≥2 个实体 label（GUI 只画这个阈值以上的，防糊） |
| `similarTo` | 写入管线自动 | `link-suggest.js` 的四道闸门（见 §6.3） |
| `before` | 写入管线自动 | 同主题 + 稀有实体重叠的时间链，方向可自愈（`fixBeforeDirections`） |
| 其余 5 型 | `memory_graph_link` 工具手动 | 需要判断因果关系时由模型或人显式连边 |

## 6.3 语义连边判定的四道闸门（v0.11.0）

`suggestLinks()` 是**纯函数**——不做 embedding、不调 LLM（向量在写入时本来就已算好），只做确定性判定，可回放：

| 闸门 | 默认 | 作用 |
|---|---|---|
| ① 阈值 | `LINK_TAU = 0.78` | 余弦低于它直接出局（与主题聚类同口径） |
| ② 互为最近邻（MNN） | `LINK_TOPK = 6` | 双方都把对方排进各自 top-K。**主力判据**，实测砍掉约一半单向噪声 |
| ③ 上下文守卫 | `LINK_TAU_CROSS_SCOPE = 0.88` | 跨 scope 的相似要求更高阈值，治"不同项目但都讲工作流"的假阳性 |
| ④ 度数上限 | `LINK_MAX_PER_MEMORY = 2` | 每条记忆每次最多新增几条，避免长成毛球 |

只处理 `LINK_LAYERS = ['sm']`（情景快照不建语义边）。同一输入永远同一输出：无随机数、无时间依赖。

## 6.4 遍历与路径

| 方法 | 走哪层 | 用途 |
|---|---|---|
| `memoryLinkNeighbors` / `memoryPath` | 记忆级边，双向 BFS | `memory_graph_neighbors` / `memory_graph_path` 工具 |
| `neighborsK` | 节点级 k-hop（递归 CTE） | 实体邻域扩散 |
| `path` | 节点级 BFS | 两个实体之间的最短链 |

## 6.5 聚类与分类的三个维度

三个维度回答不同问题，**不要混用**：

| 维度 | 实现 | 回答的问题 |
|---|---|---|
| **社区** `detectCommunities` | 标签传播（`iterations` 默认 15），**全量重算** | "哪些实体总一起出现" |
| **主题** `themeMemories` | 记忆向量凝聚聚类，label = 高频词，簇持久化在 `theme_clusters` | "这条记忆在讲什么"（语义维度） |
| **事件** `detectEvents` | 时间线扫描：相邻记忆间隔 < `events.gapHours`（默认 2h）**且**同主题 / 共享实体 | "这条记忆属于哪件事"（时间维度） |

主题分簇与事件分类在概念上的区别：主题是名词（内容分类），事件是过程（时间连续 + 因果相关）。

## 6.6 增量构建（v0.9.8）

启动 / 巡检**不再全量重建派生数据**：

| 数据 | 增量方式 |
|---|---|
| 主题聚类 | 只处理 `cluster_id` 为空的记忆（`theme_clusters` 存质心 / 词频 / 成员数）；维度迁移时清簇重聚 |
| 事件分类 | `meta.event_scan_at` 水位线——无新增直接跳过，有新记忆只重建尾部窗口 |

复杂度从 O(全量) 降到 O(新增 + 尾部)。全量对齐由 `tests/test-incremental.mjs` 守护。

## 6.7 GUI 图谱

数据源 `buildGraphSnapshot(store)`：一记忆一节点（只取 `sm` 层，上限 1000）+ 边 + 主题列表 + 事件列表。

节点字段：`theme` `type` `strength` `createdAt` `updatedAt` `versions`（版本数，>1 表示被更新过）`eventId` `aspect` `content`（前 160 字）。

**时间痕迹的可视化**：更新过的节点画金色年轮（环数 = 更新次数 − 1），颜色按库内相对映射出新旧色温，支持时间窗筛选与 hover 时间标签。

交互与布局分别落在纯函数模块里，可在 Node 中直接断言：

| 文件 | 职责 |
|---|---|
| `client/graph-force.js` | 力模型 + 初始布局（**布局的唯一出处**，可离线跑千帧校验） |
| `client/graph-geometry.js` | 主题轮廓：贴合凸包 / 最小外接圆（确定性 Welzl） |
| `client/layout-cache.js` | 收敛坐标存 localStorage，按节点 id 复用——打开即平衡，又能平滑接纳新节点 |

主题轮廓从 v0.10.6 起按**空间就地聚簇**逐块画，而不是给每个主题取全局凸包：实测"全体成员的最小外接圆"会被一个离群成员撑到整块画布（某主题实测 223%，就地聚簇后 105%）。
