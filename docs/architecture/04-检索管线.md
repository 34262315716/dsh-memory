# 04 · 检索管线

> 对应 v0.16.2。实现：`lib/store.js` 的 `search()`。
> 一句话：**三路各自打分 → RRF 融合 → 可选重排 → 过滤 → 确定性排序**。

## 4.1 全流程

```
query
  → tokenize（英文词取 ≥3 字符 + 中文 bigram 切分）
  路 1  FTS5：BM25（trigram 分词器，词长 ≥3 才 MATCH）
  路 2  关键词：memories.keywords JSON 交集计数 + 子串兜底（中文 2 字词）
  路 3  向量：embedder（rule / remote / onnx）→ memory_vectors KNN 余弦（vecEnabled 时）
  融合：每路按 score 排序得到 rank → RRF  Σ 1/(60 + rank)
        三路取并集（向量独有的命中不会被丢掉）
  精排（可选）：RRF 前 topK（默认 20，且候选 ≥ minCandidates 默认 3）
        → RemoteReranker → final = w × norm(RRF) + (1-w) × rerank   （w 默认 0.7）
        重排失败 → 直接用 RRF 顺序（零损失降级）
  过滤：scope 匹配 + excludeIds（防循环窗口）+ minScore（默认 0.02，RRF 量纲）
  加权：type=profile ×3 ｜ abstract=principle ×1.5 ｜ abstract=event ×0.7
  排序：score desc, id asc   ← 确定性，KV 缓存友好的前提
  命中 touch：刷新 last_access，strength = min(strength × 1.1, 5)
```

## 4.2 三路各管什么

| 路 | 擅长 | 短板 |
|---|---|---|
| FTS5（BM25） | 精确词面命中，中英文都支持（trigram 对中文子串友好） | 词长 < 3 的查询匹配不到；同义改写无能为力 |
| 关键词 | `keywords` 字段是提取器给的"要点"，比原文更抗改写；中文双字词兜底 | 依赖提取质量；词表之外的说法漏掉 |
| 向量 | 语义相似、跨措辞 | 需要嵌入服务；降级到 rule 哈希时精度显著下降 |

三路并集 + RRF 的意义：任何一路的独有命中都能进候选，不会因为另一路排得低而被丢掉。

## 4.3 权重（注入加权）

检索结果按类型与抽象层级加权——"**我怎么看待设计**"优先于"设计了什么"：

| 条件 | 权重 |
|---|---|
| `type === 'profile'`（画像） | × 3 |
| `abstract === 'principle'`（可复用原则 / 方法） | × 1.5 |
| `abstract === 'event'`（一次性事件产出） | × 0.7 |

会话预热走同一套排序（画像优先）。

## 4.4 minScore 的量纲

`injectMinScore`（默认 0.02）是 **RRF 量纲**，不是余弦相似度：

- 三路全中（各自都排第一）≈ 3 × 1/61 ≈ 0.049；
- 0.02 ≈ "至少有一路排进前十几名"。

用这个阈值而不是余弦，是因为 RRF 分数天然可比、不依赖某一路的绝对刻度。

## 4.5 确定性排序为什么重要

排序键是 `(score desc, id asc)`——**同一批写入、同一个查询，永远给出同一个顺序**。这是注入侧 KV 缓存友好的前提：命中集相同 → 注入块字符串相同 → 该块成为可复用的前缀（见 [05-注入管线](05-注入管线.md)）。

## 4.6 过滤与防循环

| 过滤 | 作用 |
|---|---|
| scope 匹配 | 只取「当前项目 scope + global」两层，项目间不串味 |
| `excludeIds` | 防循环窗口：同一个 agent 最近注入过的记忆不再重复注入（`maxRecentPerAgent` 默认 6） |
| `minScore` | 低相关不注入 |
| 归档排除 | `archived = 1` 的记忆不参与检索与注入 |

## 4.7 命中反馈（遗忘曲线的一半）

每次被检索命中：`last_access` 刷新为当前时间，`strength = min(strength × 1.1, 5)`。
另一半是惰性衰减，见 [07-遗忘与管家](07-遗忘与管家.md)。
