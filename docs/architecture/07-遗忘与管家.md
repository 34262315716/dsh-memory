# 07 · 遗忘与管家

> 对应 v0.16.2。实现：`lib/store.js` 的 `decayExpired` / `housekeeping` / `dedupScan` / `agingReport`。

## 7.1 遗忘曲线

两个方向，合起来才是"曲线"：

| 方向 | 时机 | 规则 |
|---|---|---|
| **衰减** | `turn/end` 低频触发 `decayExpired()` | 超 24h 未访问：`strength ×= exp(-0.15 × 天数)`，下限 0.1 |
| **加成** | 每次检索命中（touch） | `strength = min(strength × 1.1, 5)`，同时刷新 `last_access` |

衰减是惰性批量执行：只扫 `last_access < now - 24h` 且未归档的行，一个事务写完，空则直接返回。
`0.15/天` 意味着约 4.6 天衰减到一半——常被用到的记忆靠加成抵消衰减，长期闲置的会让位。

## 7.2 管家触发（与对话轮数解耦）

| 触发条件 | 默认 |
|---|---|
| 每沉淀 N 条记忆 | `housekeeping.interval = 20` |
| 距上次巡检超 N 小时 | `housekeeping.maxIntervalHours = 24` |

两者任一到期即巡检，时间戳持久化在 `meta` 表（跨重启连续）。

## 7.3 巡检做什么

`housekeeping({ dryRun, ... })`：

```
① dedupScan(threshold)     → 相似度 ≥ dedupThreshold（默认 0.92）的近重复对
② agingReport(days)        → 闲置超 agingDays（默认 30）的低强度记忆
③ dryRun === false 时才动手：
     · 近乎重复（sim ≥ autoMergeThreshold 默认 0.95）→ 择优保留一条，**其余归档**
     · 陈旧情景快照（ep + 闲置超 archiveEpAfterDays 默认 45 天 + 强度从未升过）→ 归档
④ 返回 { duplicates, aging, merged, archivedEp, details }
```

**归档 ≠ 删除**（见 [02-数据模型](02-数据模型.md) §2.4）：退出检索与注入，但数据、版本链、图谱边全部保留，`memory_archive` 可一键恢复。

## 7.4 v0.12.1 的纠偏：合并 vs 归并

旧实现把两条相似记忆用 `\n---\n` **拼起来**——越拼越长（库内实测最长 9099 字，同一句"早上好啊"被拼了三遍）。那不是整合，是堆叠。

现在的分工：

| 情形 | 做法 |
|---|---|
| 近乎完全重复（sim ≥ 0.95） | 择优保留一条（强度高者优先，同强度取内容更全的），其余归档。**不做任何拼接** |
| 讲同一件事但表述不同（0.92 ~ 0.95） | 交给 **LLM 归并器**（`consolidate=true`）合成为一条更完整的结论 |

工具面：`memory_housekeeping` 默认 `dryRun: true`（只报告），传 `dryRun: false` 才执行；`consolidate: true` 追加 LLM 归并（会消耗模型额度）。

## 7.5 治理动作的可见性

治理不是黑箱——三个地方都能看见：`memory_housekeeping` 的返回报告、GUI 记忆日志面板、会话预热块。所有动作**只归档、不删除**，做错了随时捞回来。
