# 10 · 工程约定

> 对应 v0.16.2。这一章是"写代码时不能违反的规则"，每条都有真实事故做背景。

## 10.1 防崩溃隔离（最高原则）

**插件的任何问题都不能炸掉 dsh**——dsh 必须活着，agent 才能回来修。具体到四个层面：

| 层面 | 做法 |
|---|---|
| `apply` 顶层 | 逐段 try/catch：设置面注册失败有兜底、初始化失败则停用记忆功能、Web API 失败仅 warn |
| 工具注册 | `makeSafeRegister`：单个工具 schema 非法只跳过该工具，其余照常注册 |
| 写入管线 | 整体 try/catch；向量写入失败仅 warn 跳过（`reembedMissing` 事后补写） |
| 日志 | `store.log` 自己吞异常——日志写不进绝不影响主流程 |

## 10.2 依赖注入：模块级函数不碰 apply 局部变量

`attachWritePipeline` / `attachInjectPipeline` / `attachPreheatPipeline` 的依赖一律通过 `deps` 显式传入：
```
{ store, getCfg, wsRegistry, logStore }   // (inject 另有 workProjection)
```
工具注册器同理（`registerTools(ctx, store, getCfg)`）。

**管线与工具绝不访问 `apply` 的局部变量**——这是 v0.9.6 那次事故固化的规则：函数依赖闭包外的状态，测试无法构造、重构必崩。

## 10.3 分层与单向依赖

- 底层（`util` / `store`）**永不 import 上层**（`pipelines` / `tools` / `index`）。
- 高层只 import 它真正消费的东西。
- 新模块照 [01-模块构造](01-模块构造.md) §1.3 的层次图摆放。

## 10.4 测试

测试统一放 `tests/`（28 个文件），改 `lib/` 后跑全量。按关注点分三类：

| 类别 | 文件 |
|---|---|
| 阶段回归 | `test.mjs`（阶段一）`test-phase2.mjs` `test-phase3.mjs` |
| 子系统专测 | `test-embedder` `test-health` `test-refiner-thinking` `test-refiner-retry` `test-refiner-slim` `test-refiner-truncation` `test-housekeeping` `test-governance` `test-events` `test-incremental` `test-update-append` `test-edge-types` `test-keyword-filter` `test-link-suggest` `test-semantic-links` `test-tool-add` `test-rewrite` `test-write-gate` `test-inject-pipeline` `test-conversation-flow` `test-profile` |
| 纯函数守护 | `test-graph-field`（力模型）`test-graph-geometry`（几何）——无需副本环境，Node 里直接跑 |

依赖 `@deepseek-ai` 包的套件需要在部署副本环境运行，或在源码目录把 `node_modules` 挂 junction 指向 harness。

具体每个套件的项数与覆盖点见 [README §测试](../../README.md)。

## 10.5 运行日志

所有关键动作都走 `store.log(level, event, detail, scope)`：初始化、预热、注入、写入、蒸馏、降级、管家、事件检测、连边修复、每一次工具调用。

- 事件名是稳定的（如 `inject` / `write` / `refined` / `fallback` / `housekeeping`），便于按事件筛选排查。
- 惰性裁剪：每 64 条插入清一次超额旧日志（`logging.maxRows` 默认 2000）。
- 三个查看入口：GUI「记忆日志」面板、`memory_logs` 工具、`/dsh-memory/logs` 端点。

## 10.6 scope 三态

`scopeOf(session, registry)` 是唯一判据：`cwd → workspaceRegistry → global`。禁止在别处重复实现这套逻辑——散布的副本一定会漂移。

## 10.7 版本与部署纪律

每次改动 = 实现 + 测试 + CHANGELOG + 部署副本同步 + 提交推送。收工前 `node tools/deploy.mjs --check`。

**改动 `lib/` 或客户端 bundle 需重启 DSH 才生效**；只改客户端面板的话，重建产物 + 刷新页面即可。

## 10.8 文档纪律

- 禁止在文档 / 代码中出现本机绝对路径、真实凭据或密钥。
- 数据安全：记忆库文件、凭据、备份一律不入版本库（见 `.gitignore`）。

## 10.9 新增东西时的检查清单

| 动作 | 附带 |
|---|---|
| 加配置项 | `lib/config.js` + `client/settings.jsx`（若需 GUI） |
| 加工具 | `lib/tools/<域>.js` + `tools/index.js` 挂载 + 清单守护测试同步 |
| 加数据表 | `lib/store.js` 的 `SCHEMA` + 补列 / 迁移（老库兼容） |
| 加 GUI 视图 | `client/<view>.jsx` + `client/index.jsx` 插槽 + `node build-client.mjs` |
| 改公网端点 | 确认 `web-fence` 覆盖到 |
| 新模块 | 照单向依赖摆放，别让底层 import 上层 |
