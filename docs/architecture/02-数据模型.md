# 02 · 数据模型

> 对应 v0.16.2。单库 SQLite（`node:sqlite`，零编译），WAL 模式 + STRICT 表。
> 默认位置 `~/.dsh/memory.db`；运行期可能出现 `.db-wal` / `.db-shm` / `.bak-*` 伴生文件，**一律不入版本库**。

## 2.1 表清单

### 记忆主体

| 表 | 说明 |
|---|---|
| `memories` | 记忆身份 + 活跃切片。字段：`id` `layer(ep\|sm)` `type` `scope` `content` `keywords` `strength` `last_access` `created_at` `updated_at` `theme` `abstract` `profile_aspect` `archived` `pinned` |
| `memory_versions` | 世界线版本：`memory_id` `revision` `content` `keywords` `valid_from` `valid_to` `superseded_by` |
| `memories_fts` | FTS5 虚拟表（`tokenize = 'trigram'`，原生支持中文子串） |
| `memory_vectors` | `sqlite-vec` 的 `vec0` 虚拟表，维度随当前 embedder |

`memories.id` 跨版本不变——**rowid 对齐**：memories 的隐式 rowid 同时是 FTS5 与 vec0 的行键，三表在同一事务里同步，删除级联清理。

### 图谱

| 表 | 说明 |
|---|---|
| `memory_links` | **记忆级语义边（一等存储）**：`from_memory` `to_memory` `type` `weight` `valid_from` `valid_to`，主键 `(from,to,type)`。GUI 投影直读，记忆级 BFS / 邻域也走它 |
| `nodes` | 实体 / 事件 / 状态节点：`kind(entity\|event\|state)` `label` `memory_id` |
| `edges` | 节点级边（8 型），实际作为 **mentions 共现骨架** |
| `node_memories` | 节点归一化后的多对多（一个实体属于多条记忆） |
| `communities` / `community_members` | 社区聚类（label propagation 产物） |

8 型边（`EDGE_TYPES`）：`mentions` `partOf` `similarTo` `causes` `solves` `before` `supports` `contradicts`。
自动建边目前只覆盖 `mentions`（共现骨架）、`similarTo`（向量判定）、`before`（时间演化）；其余类型留给工具手动连边。

### 派生数据与运维

| 表 | 说明 |
|---|---|
| `theme_clusters` | 主题簇持久化：`centroid` `keywords` `member_count`——增量聚类的基础 |
| `events` / `event_members` | 事件分类（时间连续 + 因果相关），时间线扫描的产物 |
| `meta` | 键值元数据：管家时间戳、`event_scan_at` 水位线、蒸馏幂等记录 |
| `logs` | 运行日志（全链路埋点），惰性裁剪到 `logging.maxRows` |

### 索引

```
idx_versions_active      memory_versions(memory_id) WHERE valid_to IS NULL   ← 活跃版唯一
idx_versions_memory      memory_versions(memory_id)
idx_memories_scope       memories(scope)
idx_memories_layer       memories(layer)
idx_edges_from / _to     edges(from_node) / edges(to_node)
idx_node_memories_mem    node_memories(memory_id)
idx_memory_links_from/_to memory_links(from_memory) / (to_memory)
idx_event_members_mem    event_members(memory_id)
idx_logs_ts              logs(ts DESC)
```

## 2.2 补列迁移（老库自愈）

初始 `SCHEMA` 之外，以下几个列是**运行时检测缺失再补**的（新装库直接建全，老库自动 `ALTER TABLE`）：

| 列 | 引入 | 用途 |
|---|---|---|
| `theme` | v0.10 | 名词标签（如"四级备考"） |
| `abstract` | v0.10 | 抽象层级：`principle` / `event` |
| `profile_aspect` | v0.10 | 画像子域（identity / preference / habit / background / communication_style） |
| `cluster_id` | v0.9.8 | 主题聚类增量标记：空 = 待归簇 |
| `archived` | v0.12.1 | 归档标记（治理产物，归档 ≠ 删除） |
| `pinned` | v0.13.0 | 常驻标记（恒定注入，不走检索） |

补列失败只 `console.warn`，不中断启动——遵循"防崩溃"总则（见 [10-工程约定](10-工程约定.md)）。

## 2.3 世界线语义（时间维度）

`features.time` 开启时：

- **更新 = 追加版本 + 改写活跃切片**。旧版本 `valid_to` 置非空（隐藏，不参与检索/注入），内容永不销毁。
- `maxVersionsPerMemory`（默认 8）滚动裁掉最旧版本。
- **回滚 = 把旧版重新激活为新 revision**（`memory_rollback`）——世界线不断链，回滚这件事本身也留下版本记录。
- 活跃版唯一性由部分索引 `idx_versions_active` 保证。

关掉 `features.time` 时，更新只改 `memories` 行，不写版本表。

## 2.4 归档语义（治理产物）

- 归档 = `memories.archived = 1`：**退出检索与注入，但数据、版本链、图谱边全部保留**。
- 检索、统计、注入默认都排除归档记忆；`memory_archive` 工具可列出并一键恢复。
- 归档与删除的区别是治理设计的核心：管家做错了随时能捞回来。

## 2.5 向量表与降级

- 维度由 embedder 决定（`VEC_DIM = 256` 是 rule 兜底；远程模型按实际维度建表）。
- 换模型导致维度变化 → 清空向量表 + 全量重嵌入（`reembedMissing`，期间 FTS / 关键词路照常）。
- `sqlite-vec` 加载失败 → `vecEnabled = false`，检索自动降级到 FTS / 关键词两路，主体功能不受影响。
- 远程嵌入初始化失败 → **进入降级态**：禁止破坏性维度迁移、保留现有向量表、暂停向量路（见 [08-配置与双内核](08-配置与双内核.md) §降级保护）。
