# 08 · 配置与双内核兼容

> 对应 v0.16.2。实现：`lib/config.js`（schema）+ `lib/compat.js`（兼容层）+ `client/settings.jsx`（面板）。
> 本机同时存在两代内核（0.1.x 与 0.2.0-rc.2），插件必须两代都能跑。

## 8.1 配置三源合一

```
schema 默认值（lib/config.js）
     ← 组合层（cordis.patch.yml 的 config，作为 base）
     ← 用户层（GUI 写入 settings.yaml 的 memory 段）
```

**读值唯一入口**：`getCfg()` = `plainConfig(老内核 settingsScope.get() | 新内核 config.get() | 原始 config)`。
`plainConfig()` 只在真含 `Volatile` 时重建对象——老内核上零开销。

## 8.2 两代内核的"注册"是两件事

`lib/compat.js` 的 `createSettingsFace()` 按**服务能力**（不是版本号）择一：

| | 0.1.x | 0.2.0-rc.2 |
|---|---|---|
| 注册 | `ctx.settings.register(settingsNamespace('memory'), Config, { base, applies:'live' })` | `dsh-settings` 已删除 `register`；"注册"= **导出 Config + 一条 id 唯一的 profile entry**，面板按 entry id 列表单 |
| 声明自管 | — | `ctx.settings.configure({ auto: false }, ctx.fiber)` |
| 读值 | `ctx.settingsScope.get()` | `ctx.settings.describe({ redactSecrets: true }).find(d => d.ns === entryId)?.value` |
| client 取值 | `ctx.get('settingsScope').bind({ namespace: 'memory' })` | `ctx.configForms.get(entryId)` |

⚠️ **致命约束**：绝不在模块顶层静态 import `@deepseek-ai/dsh-settings` 的命名导出。0.2.0-rc.2 上它已被删除，缺失的**命名导出**是模块求值期 SyntaxError（不是"缺失的服务"那样被静默降级），cordis 记为 entry 加载失败，**宿主直接 exit 1**。兼容层只允许"动态 import + 特性探测"。

## 8.3 只有 volatile 字段会出现在设置页

0.2.0-rc.2 上，`volatileForm()` 返回 undefined 时该字段不产生 descriptor → **整个 entry 在设置页里不存在**。
所以 `Config = volatileTable(z.object({...}))` 是**整表** volatile（`lib/config.js`）。代价：`Config(x)` 解析出来是 cosmokit `Volatile`，读值要先解包——这正是 `plainConfig()` 存在的原因。

entry id 候选：`memory`（随包 patch 用）→ `dsh-memory`（历史上手工挂载用过）。客户端两个都认，所以换挂载方式时设置面板不会掉。

## 8.5 密钥与凭据

- 密钥写在 **凭据文件** `~/.dsh/.credentials.yaml`（`api.credentials.set`），**不进设置文档、不进记忆库**，界面只回显"已配置"布尔。
- 选中供应商后，GUI 密钥输入框的目标引用自动切换为该供应商声明的 `apiKeyEnv`。
- 每个服务独立密钥槽：`MEMORY_REFINER_API_KEY` / `MEMORY_EMBEDDING_API_KEY` / `MEMORY_RERANK_API_KEY`。

## 8.6 Web 端点围栏

三个端点 `/dsh-memory/{graph,logs,health}` 走 `lib/web-fence.js`：**框架不替插件鉴权**，"路由不继承 Connection 的认证体系"（框架头注释原话）。

围栏规则：`socket.remoteAddress` 必须是回环地址（`127.0.0.1` / `::1` / `::ffff:127.0.0.1`），并校验同源，另附安全响应头。
为什么需要它：任何能触达端口的页面原本都能让 `/dsh-memory/health?llm=1` **真发一次模型请求（要花钱）**，或读走整个记忆图谱与运行日志。

> 手机 / 局域网 / 反向代理访问要显式把 `features.webFence` 设为 `off`——清楚这意味着什么再关。

## 8.7 降级保护（v0.9.31）

内存/网络出问题时的护栏，直接决定数据安全：

| 状况 | 行为 |
|---|---|
| 配置了远程嵌入但初始化失败 | **进入降级态**：禁止破坏性维度迁移、保留现有向量表、暂停向量路（FTS / 关键词照常）；网络恢复自动回来 |
| `sqlite-vec` 加载失败 | `vecEnabled = false`，两路检索继续 |
| 重排失败 | 直接用 RRF 顺序（零损失） |
| 向量写入失败 | 只 warn 跳过，`reembedMissing` 事后补写 |

## 8.8 误配置护栏（v0.12.7）

启动时检测"**强制思考的模型 + 设了 maxTokens**"这个组合并吼一声——它会把 token 额度**全花在 reasoning 上**，正文一个字不剩，JSON 解析必失败，提取持续降级。

实测：settings 里残留 `maxTokens: 800` 时，`finish_reason=length`、`reasoning_tokens=800`、正文 0 字；同一请求不传上限则 `finish=stop`、正文 2030 字、JSON 直接可解析。默认 `maxTokens: 0`（不传该参数）就是为了别再踩。

## 8.9 连通性自检（v0.11.1）

设置面板顶部「连通性自检」→ `GET /dsh-memory/health?llm=1`：对**嵌入 / 重排 / 提取**各发一次真实最小请求，并同时报出配置值、凭据存在性、向量路实况（谁在算向量、几维、多少条、是否降级）。

为什么要它：「● 已配置」只证明凭据文件里有这个键，不证明它**能用**。真实事故：上游 402 余额不足 → 嵌入静默降级到 rule 哈希、重排每次白等，界面上一切正常。
现在 `stats()` 一并返回 `vecDim / vecRows / embedder / degraded`——`embedder: "rule"` 就是那句一直没被说出口的实话。
