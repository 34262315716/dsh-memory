# 05 · 注入管线

> 对应 v0.16.2。实现：`lib/pipelines/inject.js`（两个工厂）+ `lib/work-projection.js`。
> 一句话：**把相关记忆以"并入本步 decision"的方式送进模型上下文，不额外占回合；并保证同样的命中集产生同样的文本**。

## 5.1 pre-step 检索注入

挂载点 `agent/pre-step`（waterfall），产出并入本步 `decision.messages`：

```
① 取查询文本
     用户步   → source.kind === 'user' 的真实消息（注入内容永不当查询）
     工具步 / 自主轮次 → lib/work-projection.js 折叠出的"最近在干什么"
② 去抖：query 签名与上次相同 → 跳过
③ 节流：距上次全量检索不足 N 步 → 跳过（N 由注入节奏档位决定）
④ store.search([项目 scope, global]) → 按 token 预算贪心装入（injectMaxTokens 默认 800）
⑤ 块 hash 去抖：与上次注入的块相同 → 不注入
⑥ agent.inject(createUserMessage({ form: 'recall' })) + 写运行日志
⑦ 防循环窗口：记录本次注入的记忆 id（maxRecentPerAgent 默认 6）
```

### 两个触发源（v0.16.0）

| 触发源 | 何时触发 | 日志标记 |
|---|---|---|
| **用户消息** | 每条用户消息、且文本与上一条不同（**不看步距**） | `trigger: user-message` |
| 步距 | 工具步 / 自主轮次之间，距上次检索满 N 步 | `trigger: interval` |

修的是这个缺口：步距按"步"计，而一轮用户消息通常只走几步——平稳档（12 步）下用户连问几句新问题，整段都在吃几句之前那次检索的结果。两条触发源共用下游的检索 / 预算 / 去抖管线，可用 `features.userMessageTrigger` 关掉。

### 注入节奏档位

| 档位 | 步距 |
|---|---|
| `aggressive` 激进 | 每 4 步 |
| `steady` 平稳（默认） | 每 12 步 |
| `lazy` 懒惰 | 每 30 步 |
| `custom` 自定义 | `stepInterval`（1~60） |

取值一律经 `resolveStepInterval()`，不在别处再算；写错档位回落 steady，不抛错。

## 5.2 常驻通道（钉选记忆，v0.13.0）

被显式钉选的记忆（`memories.pinned = 1`）**不走检索**、每次注入都恒定在场——回答的是"珍贵教训要一直注入，而不是讲到相关话题才冒出来"。

- 预算独立：`pinnedMaxTokens`（默认 600）与检索块分开计费，互不挤占。
- 条数上限 `pinnedLimit`（默认 8），单条截断到 `PIN_ITEM_CHARS`（260 字）。
- 工具：`memory_pin` 钉选 / 取消 / 查看清单。

## 5.3 会话预热（双通道，v0.14.0）

会话开场先把"用户是谁 + 最近在做什么"喂进去，**不占对话回合**。

| 通道 | 内核 | 机制 |
|---|---|---|
| A | 0.2.0-rc.2 | `agent/created` → `agent.ctx.inject(['systemPrompt'])` → `systemPrompt.section({ name:'dsh-memory:preheat', text: () => 预热文本 })`，系统提示段落每步重算；`agent/disposed` 时 dispose 该 fiber |
| B | 0.1.x | `agent/session-start` → `agent.inject(createUserMessage({ form:'recall' }))`（消息级注入） |

- 择一判据：`features.preheatRoute`（`auto` 默认 / `prompt-section` / `message`）。`auto` 看 `ctx` 上有没有 `systemPrompt` 服务——有走 A，没有交给 B。
- 两条通道共用 `warmed` WeakSet，保证同一个 agent 只预热一次。
- 内容顺序：画像全 scope 直取（跨项目）→ 非画像先当前项目 scope、不足再补 global。

## 5.4 工作上下文投影（v0.15.3）

`lib/work-projection.js` 注册一个官方 `sessionProjections` 单元（key `memoryWork`），由**框架**订阅 `session/event` 并把每个已提交事件折叠成状态；插件侧只在 pre-step 读 `stateOf()`，自己不持有订阅、不回看历史日志。

它解决的是"没有真实用户文本的步"（工具步、自主轮次、goal 长任务）拿不到检索 query 的问题——以前那类步在 `if (!queryText && pinned.pins.length === 0) return next()` 处静默早退，等于整段不检索。

## 5.5 KV 缓存友好

四件事一起保证"相同命中集 → 相同注入文本"：

1. **稳定块头**：标题、扫描规则固定，不掺时间戳之类的可变字段；
2. **确定性排序**：`score desc, id asc`（见 [04-检索管线](04-检索管线.md) §4.5）；
3. **append-only 尾部**：新增命中追加在末尾，不改动已有行；
4. **溯源锚点**：每条记忆带 `#mem-id`，模型能引用、人能回查。

效果：命中集不变时，注入块本身就是可复用的前缀——不因它而让整个上下文缓存失效。
